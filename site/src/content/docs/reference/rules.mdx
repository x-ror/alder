This page is the catalogue of rules, each with an example. Rule names are the diagnostic codes, and the config file described below is read for them.

The formatter and the checks work without configuration, and a `.ruby-templates.toml` changes them. [Formatting](/vscode-ruby-templates/guides/formatting/) describes what the formatter does, and the [diagnostics reference](/vscode-ruby-templates/reference/diagnostics/) lists every code the checks report.

## How to read an entry

- **Type.** An _autofix_ is a formatter rule that rewrites the template. A _warning_ is a check that reports a problem and rewrites nothing.
- **Rendered output.** _Safe_ means the rule leaves the rendered page as it is: it only changes whitespace the browser ignores, or changes markup into an equal form. _Not safe_ says what can change.
- **Examples.** An autofix shows the template before and after. A warning shows a flagged template and a fine one. The examples are run through `ruby-templates format` and `ruby-templates check` by the tests.
- **Defaults.** A formatting rule says whether it is on by default. `Layout/TrailingEmptyLines` is, for Haml and Slim, and so are `Layout/TrailingWhitespace` (all three languages) and `Layout/IndentationStyle` (ERB, which writes spaces unless the editor, `.editorconfig` or its `style` say tabs); the others, `Layout/EmptyLines` among them, are off until you turn them on, so a file is never changed beyond what the entry says unless you ask. The checks (lint rules) are on, except `Style/ErbTrimMode` and `Layout/LineLength`.

## Configuration

Rules, and the switches that VS Code has as settings, are configured in a `.ruby-templates.toml`. The editor, `ruby-templates check` and `ruby-templates format` read the same file. A rule is a table named after it, with the department and the rule joined by a dot (`["Html/ImgAlt"]` in quotes is an error, and the message says how to write it):

```toml
[Html.ImgAlt]
enabled = false
```

A department table with only `enabled` switches its rules: `enabled = false` turns them all off, `enabled = true` turns back on the ones that are on by default (cancelling a `false` from a file above) and never one that is off by default, which needs its own `enabled = true`. A rule's own `enabled` beats its department's:

```toml
[Html]
enabled = false

[Html.DuplicateId]
enabled = true
```

To change a rule for some files only, give it `include` or `exclude` globs. They follow the EditorConfig syntax (`*`, `**`, `?`, `[abc]`, `{a,b}`): a pattern without `/` matches in any folder, one with a leading or inner `/` is anchored to the folder of the file that holds it.

```toml
[Html.ImgAlt]
exclude = ["**/*.haml", "app/views/legacy/**"]
```

A rule with options takes them in its own table. `max` and `max_line_length` are whole numbers, 0 or more; `style` is one of a few words; `tags` is a list of element names. A value that does not fit is a problem in the file:

```toml
[Layout.EmptyLines]
enabled = true
max = 2

[Layout.EmptyLinesAroundBlockBody]
enabled = true
style = "empty_lines"

[Layout.ElementContentOnOwnLine]
enabled = true
tags = ["div", "section"]
```

### All keys

```toml
root = true                        # stop looking in the folders above
exclude = ["vendor/**", "tmp/**"]  # no checks and no formatting for these files

[erb]
format.enabled = false             # no formatting for ERB
format.align_comments = true       # same as --align-comments
diagnostics.enabled = true         # false: no diagnostics for ERB

[haml]                             # format.enabled, diagnostics.enabled
[slim]                             # the same, and: extra_engines = ["mjml"]; Skim files too
```

Lowercase tables are languages and take the keys of the `rubyTemplates.<language>.*` settings, in snake case; capitalised tables are departments and rules. A key under the wrong table (`extra_engines` under `[erb]`) is reported. To switch a rule off for one language, give it `exclude` globs (`[Html.ImgAlt] exclude = ["**/*.haml"]`); the former `disabled_diagnostics` key and `[jbuilder]` table are reported as problems.

### Which file applies

- The file looks for `.ruby-templates.toml` in the template's folder and every folder above it, nearest first, and stops at one with `root = true`.
- The files merge key by key: the nearest file that sets a key wins. A list (`exclude`, `include`, `extra_engines`) is replaced, not extended. Globs are relative to the folder of the file that holds them.
- The file is stronger than VS Code: precedence is the nearest file, then the VS Code settings (where no file says anything), then `.editorconfig` for the indentation width and, for ERB, `indent_style` (the editor's `insertSpaces` counts as VS Code here), then the defaults. `style` of `Layout.IndentationStyle` is a file setting, so it beats `insertSpaces` and `indent_style`.
- A rule listed in `rubyTemplates.<language>.disabledDiagnostics` is off, unless the nearest file that sets the rule's `enabled` or its department's says `true` (a department's `true` counts for a rule that is on by default only). A rule that file switches off is off whatever the setting says.
- The switch of a rule is the `enabled` of the nearest file that sets the rule's own or its department's; within that one file, the rule's own beats the department's. Without one, the rule's default applies. A department's `enabled = true` only counts for a rule that is on by default; a rule that is off by default (most formatting rules, `Layout/LineLength`, `Style/ErbTrimMode`) is turned on by its own `enabled = true` only. A root file with `[Html.ImgAlt] enabled = true` and a `legacy/` file with `[Html] enabled = false` therefore leave `Html/ImgAlt` off under `legacy/`. A rule that is off (its own or its department's `enabled = false`, or left out by `include`/`exclude`) does nothing, which for the two rules that are on by default means the old behaviour: `Layout/IndentationStyle` off writes spaces whatever the editor or `.editorconfig` say, and `Layout/TrailingWhitespace` off keeps the whitespace at the line ends, so `[Layout] enabled = false` stops that trimming too. Then the rule's `include` and `exclude` apply, and the rule must exist for the file's language. A file in the global `exclude` gets no diagnostics and is not formatted.

### Problems in the file

A key or a value the server can't read is dropped, and the rest of the file is used. A file that exists but can't be read (not UTF-8, no permission, a folder with that name) is one problem at its first line. Problems show on the `.ruby-templates.toml` itself in the Problems panel, and in the _Ruby Templates_ output, once a template it applies to is open or formatted; they refresh when the file is saved. A `.ruby-templates.toml` above the workspace folders is watched too, if the editor allows it. `ruby-templates check` prints a problem as `file:line:column: warning: message [Config/Invalid]` and exits with 1, and `format --verbose` prints it too. A file that isn't valid TOML is ignored whole.
